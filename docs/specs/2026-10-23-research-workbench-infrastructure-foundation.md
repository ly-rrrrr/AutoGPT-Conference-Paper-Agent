# 科研工作台基础设施底座

## 决策

当前阶段停止扩展语料认知提示词，优先建设能够长期承载单篇精读、论文篮子和多视角综述的数据底座。

系统采用三个边界明确的核心服务：

- PostgreSQL：论文、作者、会议、AI 产物、来源、版本、任务和用户操作的权威业务记录；
- Milvus：论文级、章节级、段落级和未来图片级向量的可重建检索索引；
- GROBID：把学术 PDF 转换成带章节、段落、参考文献和位置关系的 TEI XML。

Milvus 和 GROBID 都不是业务事实来源。删除它们的索引或解析产物后，系统应能依据 PostgreSQL 记录与保留的原始资产重建。

外部聊天与 Embedding 请求统一使用工作台出站代理边界。Windows 默认自动读取当前用户的系统代理，显式 `WORKBENCH_OUTBOUND_PROXY_URL` 优先；本机 PostgreSQL、Milvus 与 GROBID 请求不经过该代理。

## 本机部署

Docker Compose 运行：

- PostgreSQL 16；
- Milvus 2.6.24 Standalone；
- Milvus 所需的 etcd 与内部 MinIO；
- GROBID 0.9.1。

Milvus 只监听本机 `127.0.0.1:19530`，管理与健康界面只监听 `127.0.0.1:9091`。其 etcd 和内部 MinIO 不向宿主机公开端口。所有镜像均固定版本，避免启动时静默升级。

启动器允许 Milvus 和 GROBID 在后台首次下载，不阻塞 PostgreSQL、资产同步和工作台网页。`/api/health` 分别报告数据库、向量服务和 PDF 解析服务状态。

## 数据所有权

PostgreSQL 保存：

- 稳定论文 ID 与会议归属；
- 原始文件和派生产物的路径、哈希与版本；
- 向量记录的逻辑 ID、嵌入模型、维度和索引版本；
- 精读、综述和研究任务的状态与成本。

Milvus 保存：

- 稳定逻辑 ID；
- embedding；
- 用于过滤和回查的最小标量元数据；
- 指向 PostgreSQL 记录和原始文本位置的 ID。

Milvus 不保存唯一正文副本，也不承担论文、篮子或研究结论的关系建模。

GROBID 输出与 PDF 一同作为文件资产保留，数据库只保存路径、哈希、解析器版本和状态。

## Collection 策略

基础设施阶段不创建占位 collection。embedding 模型确定后，以向量维度和嵌入模型版本作为 collection 兼容边界。论文、段落和图片采用不同 collection，避免把不同语义粒度混进一个近邻空间。

collection 名称由工作台前缀、资产类型和安全化的模型版本组成。业务代码只依赖向量存储适配器，不直接传播 PyMilvus 数据结构。

## 后续基础设施顺序

1. 原始 PDF、GROBID TEI、框架图和派生文本的统一资产清单与内容哈希；
2. 可恢复的后台任务队列和 Worker；
3. embedding 模型配置、增量索引和去重；
4. 单篇精读证据定位；
5. 论文篮子与多视角综述。

截至 2026-10-23，前两项已经落地。每个当前资产指向按 SHA-256 去重的不可变版本；TEI 会进一步形成带章节路径、页码、定位符和独立内容哈希的正文块。`PipelineRun` 同时承担持久化任务记录，Worker 使用数据库行锁、执行租约、有限重试和事件日志接管 `lineage` 任务。网页进程中断不会再使已排队任务消失。

第三项已完成 Milvus 适配器、独立 Embedding 配置、PostgreSQL `vector_index_records` 回查边界和可恢复增量索引任务。系统有意不创建空 collection；只有用户保存 Embedding 提供商、模型和准确维度，并在知识资产页明确启动后，才建立模型隔离的 collection。配置维度会显式作为 OpenAI 兼容接口的 `dimensions` 参数发送。索引器只读取每篇论文当前内容哈希对应的资产版本，历史版本仅保留用于追溯；并按正文块内容哈希、模型、维度和索引版本跳过已成功记录，批量请求 embeddings 并批量 upsert，避免重复消耗。

Spark 当前不进入系统。只有语料达到需要跨多台机器执行全量离线转换时，才把它作为批处理工具评估；它不承担在线检索或 AI 工作流调度。
