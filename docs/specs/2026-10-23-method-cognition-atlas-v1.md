# Method Cognition Atlas V1 规格

日期：2026-10-23

## 1. 目标

用户选择一个会议年度、研究范围或开放问题后，科研工作台应主动发现值得关注的方法现象，解释其问题背景、思想来源、关键改造、跨领域迁移、实验支持与适用边界，并将结论组织成可以继续追问、比较、投影和下钻到原文的交互式认知制品。

成功不是生成更多摘要、标签或关系边，而是让用户获得传统主题统计和逐篇阅读难以直接得到的认知：同一思想如何以不同叙事出现、一个方法为何能迁移到另一个领域、哪些论文共享机制但实现不同、哪些趋势拥有证据而哪些只是叙事趋同。

## 2. 目标保真原则

1. 不从当前容易实现的引用图、关键词统计或固定字段反推目标。
2. 不用关键词、固定阈值、硬编码分类顺序或论文引用关系替代思想联系。
3. 不把任何单次模型输出、聚类或图社区当作事实；它们只能形成候选认知。
4. 允许研究路径根据目标与中间证据变化，但要求最终制品满足来源、支持、反例和不确定性契约。
5. 通用能力优先复用成熟生态，核心开发集中于科研方法语义和交互体验。

## 3. 核心用户问题

### 年度尺度

- 这一年度有哪些共同研究瓶颈正在形成？
- 哪些思想正在跨领域传播，迁移时保留和改变了什么？
- 哪些少见的方法组合开始重复出现？
- 哪些趋势具有跨论文实验支持，哪些主要停留在作者叙事？

### 方法尺度

- 一个方法家族的核心不变量是什么？
- 它有哪些重要变体、适用条件和失败边界？
- 不同论文为什么采用相似思想，却实现成不同架构？

### 论文尺度

- 作者真正面对的瓶颈是什么？
- 哪种既有思想启发了设计，论文做了什么关键改造？
- 方法的机制、架构和实验是否支持作者动机？
- 它在年度方法空间中与哪些工作相近，又在哪些维度偏离？

## 4. 主动研究循环

系统不使用一条固定的语义分类流水线。每次研究由 `ResearchBrief` 启动，AI 工作流在预算和工具边界内循环执行：

1. **Orient**：理解研究目标、范围、已有资产和缺口。
2. **Propose**：提出值得调查的问题、假设或反常现象，说明潜在价值。
3. **Explore**：自主选择论文搜索、证据检索、全文问答、相似项召回、引用遍历或结构化数据查询。
4. **Challenge**：主动寻找反例、替代解释、证据不足和范围偏差。
5. **Revise**：修改、拆分或放弃候选洞察；必要时发起新的工具调用。
6. **Synthesize**：形成带来源范围、支持、反例和不确定性的认知制品。
7. **Publish**：选择适合该洞察的表格、时间轴、方法地图、对比视图或叙事卡片。

循环终止依据是研究制品契约、预算与明确的无法回答状态，而不是出现某个关键词或达到某个相似度。

## 5. 认知制品协议

### ResearchBrief

- 用户目标与希望获得的认知；
- 会议、年份、领域、论文或已有集合范围；
- 可使用的数据源和工具；
- 时间、模型调用和外部请求预算；
- 输出语言、展示偏好和必须回答的问题。

### ResearchArtifact

所有 Agent 和工具之间持久交换的通用制品：

- `artifact_type`；
- `research_brief_id`；
- 输入制品与来源资产；
- 结构化内容和人类可读表达；
- 证据引用；
- 生成器、模型、工具、提示或程序版本；
- 状态、警告、不确定性和创建时间。

### InsightProposal

- 候选洞察；
- 为什么值得关注；
- 涉及的论文、方法、问题、领域与时间；
- 支持证据；
- 反例或替代解释；
- 尚缺证据；
- 适用范围与不得外推的边界；
- 建议的交互表达；
- `OBSERVED`、`AUTHOR_CLAIM`、`INFERRED` 或 `SYNTHESIZED` 类型。

候选洞察只有满足契约后才能成为 `PublishedInsight`。发布不表示永久真理；模型、语料或用户修订变化后可以生成新版本，旧版本保留来源链。

## 6. 工具而非固定层级

现有资产被注册为 AI 可以按需选择的工具：

- 论文目录与元数据查询；
- 已有逐篇 AI 问答查询；
- PDF 与章节证据检索；
- PaperQA2 科学文献研究；
- OpenAlex / Semantic Scholar 元数据与引用遍历；
- pgvector 语义候选召回；
- 统计聚合与时间切片；
- GraphRAG 社区和全局查询候选；
- 用户关注方向、近期工作和修订记录。

GROBID 引用结果不再被固定为后续语义层的入口。它只是 Agent 在调查思想来源或作者论述时可调用的工具之一。

## 7. 可靠性边界

### 确定性控制面

FastAPI、PostgreSQL 与 AutoGPT 管理任务身份、状态、幂等、预算、权限、版本、停止和恢复。AI 不得自行修改这些工程不变量。

### 自适应认知面

AI 决定研究问题如何分解、需要调用哪些工具、哪些候选值得追查、如何寻找反例以及采用何种表达。过程可以变化，但每一步都产生可观察的工具调用或认知制品。

### 证据与推断分离

- 原文和事实元数据不可被模型文本覆盖；
- 作者声明与系统综合必须分开；
- 没有直接证据时允许提出假设，但必须标为 `INFERRED`；
- 找不到充分证据时输出无法回答或保留争议，不得用常识补齐。

### 关键而非重复验证

- 自动检查制品 Schema、来源存在性、引文可定位性和版本闭包；
- 对年度核心洞察执行反例搜索和范围审查；
- 人工只处理高影响概念合并、迁移结论和用户明确关注的争议；
- 不对每个普通工具结果重复进行多模型投票。

## 8. 后端边界

新增框架无关接口：

- `ResearchWorkflowAdapter`：启动、继续、停止和观察研究循环；
- `ResearchToolRegistry`：向 Agent 暴露受控工具及权限；
- `ResearchArtifactStore`：版本化保存认知制品和依赖；
- `EvidenceResolver`：将外部工具引文解析为工作台论文、页码和文本片段；
- `InsightPublisher`：将合格制品投影为前端可交互数据。

AutoGPT 是首个 `ResearchWorkflowAdapter` 实现；PaperQA2、DSPy、GraphRAG、OpenAlex 和语义检索均通过独立适配器接入。核心数据库不得保存第三方框架私有对象作为唯一事实来源。

## 9. 产品信息架构

新增一级模块“方法认知”：

- **研究任务**：定义 ResearchBrief，观察 Agent 计划、工具调用、证据缺口和成本；
- **主动洞察**：按价值、范围、证据与不确定性浏览系统主动提出的 InsightProposal；
- **年度方法全景**：围绕一个洞察生成可切换投影，不预设唯一二维或三维坐标；
- **方法家族**：展示共同机制、变体、领域迁移、实验支持和反例；
- **论文方法解剖**：展示围绕当前研究目标形成的方法理解，而不是固定模板摘要；
- **认知制品库**：查看来源、版本、模型、工具、用户修订和重新生成关系。

现有论文目录、问答、引用谱系和知识库页面保留，逐步成为研究任务可调用的数据与证据入口。

## 10. V1 交付顺序

1. 建立 ResearchBrief、ResearchArtifact、EvidenceRef 和 InsightProposal 的数据库与 API。
2. 增加研究任务页面，能够提交目标并观察一个可恢复的研究会话。
3. 接入 PaperQA2 证据适配器与 DSPy 认知程序适配器。
4. 使用 VLA-R1 完成首个“思想来源、关键改造与证据边界”主动研究制品。
5. 扩展到一个用户选定的论文集合，形成首个带支持和反例的方法洞察。
6. 接入语义候选召回与语料级综合，形成会议年度的主动洞察流。
7. 根据洞察类型实现方法地图、时间轴、对比表和证据下钻，而不是先建设空白图形容器。

## 11. V1 验收

- 用户能够用自然语言指定会议范围和想获得的认知，而不是选择固定分类规则；
- Agent 能根据中间发现改变工具调用和调查路径；
- 研究过程可暂停、恢复、观察并受预算约束；
- 至少一个主动洞察同时包含支持证据、反例或替代解释、不确定性和适用范围；
- 用户能够从洞察下钻到方法、论文和原文证据；
- 相同输入和工作流版本可以重放，旧结果不会被静默覆盖；
- 没有关键词分类器、相似度阈值或引用边被直接当作最终方法关系。
