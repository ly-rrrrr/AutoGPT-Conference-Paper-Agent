# CVPR 2026 持续认知 Harness V1

日期：2026-10-23

## 目标

系统以 CVPR 2026 全部 2672 篇论文为认知分母。在没有用户预设研究问题时，仍能持续读取论文材料、自主提出研究议程、调查候选洞见、寻找反例并维护可追溯的领域认知状态。

“研究任务”保留为用户定向观察现有认知的入口，不再作为主动发现的唯一启动方式。

## 输入

- 2672 篇论文目录；
- arXiv 链接与后续 PDF/解析文本；
- 已有逐篇 AI 问答；
- Likes 等影响力信号；
- 引用、用户偏好和后续全文证据；
- 模型、并发、费用和时间预算。

影响力信号只帮助调度和观察，不决定论文质量或洞见真假。

## Harness 的职责

Harness 固定工程质量，不固定科研结论：

- 保存完整语料分母和各层覆盖率；
- 使用材料哈希、模型和程序版本缓存稳定结果；
- 根据材料变化进行局部失效，不全量重算；
- 调度并行工作、分支、循环、停止和恢复；
- 记录每次模型调用、工具调用、Token、证据和失败；
- 要求候选洞见经历支持证据与反例调查；
- 保存被拆分、合并、降级和放弃的历史版本。

AI 自主决定临时主题、研究议程、调查对象、语义联系和最终表达。

## 运行拓扑

1. **论文记忆**：复用 2664 篇已有结构化分析；只为缺失或输入变化的论文重新计算。
2. **全语料观察**：从完整论文记忆中自主提出临时研究议程，不把已有 topic 当作最终类别。
3. **候选洞见调查**：按需并行寻找支持、差异、跨领域迁移和原文证据。
4. **独立挑战**：寻找反例、覆盖偏差和替代解释；可以回到第一步要求深读。
5. **认知维护**：合并、拆分、降级、搁置或发布洞见，并触发新的调查回路。

这些是控制角色而不是固定语义流水线。任一步都可以产生新的调查分支或返回上游。

## 多 Agent 决策

- 单篇论文读取采用并行工作池，不让多个 Agent 重复讨论同一材料；
- 全语料观察优先采用单个规划 Agent 配合检索和统计工具；
- 对独立证据调查、跨领域搜索和反例搜索采用按需多 Agent；
- 最终认知维护由单个 Curator 负责，避免多个 Agent 无界聊天和重复 Token；
- 所有角色通过数据库中的版本化制品交换信息，不依赖隐含聊天历史。

## Token 经济

- 现有逐篇问答作为第一轮论文记忆，禁止无条件重做；
- 缓存键至少包含材料指纹、程序版本与模型版本；
- 提示中传递结构化制品和必要证据，不重复携带整篇论文；
- 全局发现先使用压缩后的论文记忆，只有候选洞见进入调查后才回读全文；
- 相同语料快照的重复启动直接复用；
- 页面必须区分累计调用、本轮新增调用和缓存命中。

## 生态复用

V1 选择 LangGraph 作为优先 PoC 候选，用于持久化、分支、循环、流式事件和人工中断；权威状态仍保存在工作台 PostgreSQL，通过适配器隔离框架。LlamaIndex 作为全文解析、索引和 Agentic RAG 候选。CrewAI 不作为核心控制面；AutoGen 已进入维护模式，不用于新架构。

## 当前交付边界

当前版本已经交付 CVPR 2026 全量材料快照、版本化论文记忆登记、缓存复用边界、LangGraph 零费用准备图、运行阶段、角色拓扑和网页可观察控制面。初始化 Harness 不调用模型，也不宣称已经产生全局洞见。

全语料自主发现已交付第一个可运行批次：用户明确设置模型调用上限、每批论文数和输入字符上限后，Cartographer 只读取尚未覆盖的论文记忆，自主形成批次级候选观察与研究议程。系统保存调用计数、Token、输入指纹、来源论文、模型与局限；只有引用本批次真实论文 ID 的结果才有效。每批输入会去除已有分析中的重复长文本，停止请求在当前模型调用结束后生效。批次覆盖不等于年度趋势，只有完整覆盖并经历后续证据和反例回路后才可能升级为年度洞见。

后续实现重点：跨批次合并与议程收敛、证据/反例多 Agent 回路、持续认知制品发布状态和方法/时间/领域交互投影。
