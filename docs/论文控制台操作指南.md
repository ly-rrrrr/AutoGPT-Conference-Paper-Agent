# 本机论文研究控制台

在当前 AutoGPT 工作区根目录双击 `启动论文研究.cmd`。浏览器会打开 http://127.0.0.1:8766 。请保留启动后的命令窗口。

## 日常操作

1. 打开入口后自动启动 Docker 与服务，等待提示服务已启动；失败时可点击同名按钮重试。首次需要本机已安装 Docker Desktop 和 Python，现有工作流和凭证应已配置。本入口复用本机部署，不负责在新电脑安装完整 AutoGPT。
2. 点击“开始／继续 arXiv 映射”。它从已保存的断点继续；无须等待全部映射完成才能分析。
3. 点击“开始／继续论文分析”。保持 `eccv-2026-luna-full-01` 可接着已有结果运行。页面每五秒更新文件统计；“查询后台任务状态”查询真实执行状态。
4. 点击“打开结果文件夹”，进入 `reports` 查看单篇报告，或打开 `qa-results.jsonl`。汇总文件在整轮结束后生成。

## 如何调控

- 本轮新增分析上限：默认 400；设置 20 表示本轮最多处理 20 篇未成功论文。0 表示不限。
- 并发：默认 1，最大 3。服务频繁限流时使用 1。
- 请求间隔：默认 4 秒，控制 LLM 请求启动间隔，不是每篇论文完成时间，也不控制 arXiv 检索频率。
- 参数在下一次点击开始时生效，不影响已运行任务。
- 运行名称是断点结果集名称。更换名称会重新分析，可能增加费用。
- 模型、研究问题沿用 AutoGPT 中已配置工作流。本版控制台暂不提供修改这两项的表单。

## 停止与续跑

“停止论文任务”停止本机已配置论文工作流的运行／排队执行，保留已落盘结果。“停止映射”只停止当前控制台启动的映射进程，保留逐篇断点。正在处理的论文可能需要重试，已有请求费用无法撤回。

关闭网页不等于停止。请使用对应停止按钮。关闭命令窗口后控制台不可访问；再次双击即可重新打开。不要同时从其他终端启动映射。

分析每轮读取启动时的 `mappings.jsonl` 快照。映射任务结束或正常报错退出会导出新快照；强制停止时最近进展仍在 `mapping-checkpoint.jsonl`，续跑后会重新导出。新增匹配不会自动进入已运行分析，完成后再次点击继续分析即可。

## 常见提示

- HTTP 429：外部服务限流。映射会保留断点并退出，稍后点击继续。不会自动无限重试。
- 401／凭证失效：需要在 AutoGPT 重新连接 alphaXiv 或模型凭证；启动脚本不能代替账户授权。
- 找不到 Docker／Python：先安装对应程序并重新打开入口。
- 端口 8766 被占用：优先使用已打开的控制台窗口。
- 有任务运行或排队：等待完成或点击停止后再开始，避免同一工作流重复执行。

## 数据与部署位置

控制台源码位于 `.worktrees/eccv-arxiv-mapping/scripts/`，实际数据位于 `.worktrees/conference-paper-agent/projects/conference-paper-research-agent/data/`。IDE 中前一个 worktree 的 `data` 可能是旧样本，请以实际运行目录为准。

控制台只监听本机地址。凭证继续保存在 AutoGPT 内，不在网页展示。控制台会自动查找名为 `Conference Paper Research Agent` 的已启用工作流；存在多个时使用最近运行过的一个，多个均未运行时通过环境变量 `PAPER_USER_ID`、`PAPER_GRAPH_ID` 明确指定。迁移部署还可用 `PAPER_PLATFORM_ROOT` 指向包含 docker-compose.yml 的 autogpt_platform 目录。
