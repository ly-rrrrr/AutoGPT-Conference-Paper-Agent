# 科研工作台操作指南

科研工作台是当前项目的首选本机入口。它把已有的 ECCV/CVPR 原始资产、arXiv 映射、AutoGPT 论文分析、影响力信号与个人研究偏好组织在同一个层级化网页中。

## 最简单的启动方式

在仓库根目录双击：

```text
启动科研工作台.cmd
```

首次启动可能需要几分钟。启动器会在后台下载 GROBID 学术解析镜像，不再阻塞网页入口；下载完成前仍可浏览论文和已有数据，但不能生成新的相关工作谱系。默认使用适合本机 CPU 的 `0.9.1-crf` 镜像；如需试验深度学习模型，可通过 `GROBID_IMAGE=grobid/grobid:0.9.1-full` 显式切换，但 full 镜像约 8 GB 且更依赖内存/GPU。脚本会依次：

1. 检查并在需要时启动 Docker Desktop；
2. 创建独立的 Python 环境并安装工作台依赖；
3. 启动工作台专用 PostgreSQL，并在后台准备 GROBID 学术文献解析服务；
4. 在缺少网页产物时安装前端依赖并构建 Vue 页面；
5. 执行数据库迁移，并把已有 JSONL 资产幂等同步进 PostgreSQL；
6. 打开 <http://127.0.0.1:8767>。

请保留启动后的命令窗口。关闭窗口会停止网页服务，但 PostgreSQL、原始论文文件、映射断点和分析结果仍会保留。再次双击即可恢复入口。

## 页面如何使用

- **工作台 → 研究总览**：查看论文总量、会议构成、映射/分析漏斗和 Likes 信号。这些数字是历史累计，不等同于本轮新增。
- **论文资产 → 论文目录**：按会议、映射状态和分析状态筛选，支持标题搜索与 Likes 排序。点击标题进入详情。
- **论文资产 → 相关工作谱系**：选择一篇已映射论文，明确触发 PDF 获取与 GROBID 解析；随后按继承、改进、问题缺口、方法差异、实验比较、采用和一般引用查看关系图及正文证据。
- **论文资产 → 运行记录**：查看从工作台发起的映射与分析任务、参数和状态。凭证与完整容器日志不会进入页面。
- **方法认知 → 研究任务**：把年度趋势、方法迁移或论文深挖写成明确的研究目标，并保存会议、年份、调用预算和输出偏好。当前页面已经启用研究任务与版本化认知产物仓库；PaperQA2、DSPy 和主动研究适配器会显示真实接入状态，未就绪时不会伪装成可运行。
- **采集与分析 → arXiv 映射**：启动或停止 ECCV 映射。它访问 ECCV/arXiv，但不调用付费模型；断点自动保存。
- **采集与分析 → 论文分析**：设置运行名、并发、请求间隔和本轮新增上限。只有点击“确认并启动分析”后才会调用 AutoGPT；打开页面和刷新状态不会产生模型费用。
- **知识库 → 文档资产**：观察 PDF/TEI 的 `MISSING`、`AVAILABLE`、`PARSING`、`PARSED`、`FAILED` 状态。只有在谱系页面点击“生成 / 更新谱系”才会获取并解析单篇论文；不会自动批量处理全部论文。
- **个性化 → 研究偏好**：维护研究方向、关键词与可解释评分权重。机器导入数据和用户偏好分别保存。
- **系统设置 → 模型配置**：维护 OpenAI 兼容供应商、Base URL、模型名称、默认配置和 API Key。密钥只写入当前 Windows 用户的系统凭据库，工作台 API 不返回明文；更新其他字段时密钥框留空即可保留原密钥。

## 数据同步与论文分析不是一回事

每次启动时的“同步已有论文资产”只读取本地 JSONL/Markdown 等结果，将变化导入工作台数据库。它是幂等的，不会重新运行映射，也不会调用模型。

论文分析必须在“论文分析”页面由你明确确认。相同 `run_id` 会沿用现有断点；更换名称可能重新处理论文并增加费用。推荐先用较小的“本轮最多新增分析”（例如 20）观察结果，再扩大批次。

“研究任务”也不会在保存草案时调用模型。它先保真地记录你真正想回答的问题，供后续目标驱动的主动研究运行时使用。运行时将按需提出候选认识、读取论文、寻找支持与反证并修订表达，而不是把论文依次送入固定关键词或固定分类规则。

配置默认模型后，可以在任务详情点击“启动主动研究”。这会产生模型费用；工作台首先让模型查看真实语料覆盖，再由模型自主调用范围概览、论文搜索和论文分析读取工具。形成的洞察、反方解释、开放问题、引用论文与运行计数会分别保存。页面显示的“范围内论文/已有结构化分析”是本次任务能够使用的材料边界；材料不足时不应把结果解释为完整年度趋势。

## 数据位置

- 权威原始资产：优先读取当前 AutoGPT 运行项目的 `projects/conference-paper-research-agent/data/`；找不到时读取本仓库 `data/`。
- 工作台数据库：Docker 命名卷 `workbench_postgres_data`，端口只映射到本机 `127.0.0.1:55432`。
- Vue/FastAPI 源码：`workbench/frontend/` 与 `workbench/backend/`。
- 谱系 PDF 与 GROBID TEI：`workbench/data/papers/<paper-id>/`，数据库仅保存索引、状态和来源哈希。
- 映射日志：数据目录下的 `workbench-mapping.log`。

如需强制指定数据目录，在启动前设置 `WORKBENCH_SOURCE_ROOT`。AutoGPT 平台仍可使用 `PAPER_USER_ID` 与 `PAPER_GRAPH_ID` 消除多个同名工作流带来的歧义。

## 常见问题

- **提示未找到 Docker**：安装 Docker Desktop 后重新双击；如果已安装但启动超时，请打开 Docker Desktop 查看提示。
- **首次前端构建失败**：确认已安装 Node.js 与 pnpm，再重新启动。构建成功后日常启动不再要求重新构建。
- **端口 8767 已占用**：若工作台已经打开，启动器会直接复用；否则关闭占用该端口的程序后重试。
- **分析页无法读取 AutoGPT 状态**：先确认 AutoGPT 的 `rest_server`、`executor` 等服务正在运行。浏览论文和管理工作台数据不依赖它们。
- **HTTP 429**：外部检索受到限流。映射会保留断点，稍后再次启动即可。
- **数据库异常但原始文件正常**：工作台数据库是可重建索引，权威 JSONL 不会被修改。必要时可停止工作台数据库、重建卷并再次启动同步；操作前仍应确认目标仅为 `workbench` Compose 项目。
- **谱系页显示 GROBID 未就绪**：首次启动时镜像会在后台下载，工作台网页不必等待。请在 Docker Desktop 中确认 `workbench-grobid-1` 正在运行；若下载失败，再次双击启动器会重试。出现 Docker Hub 超时或镜像层解压错误通常是下载链路中断，先恢复网络后重试；若 full 容器反复退出，再提高 Docker 内存到 6 GB 或以上。
- **谱系生成后只有“一般引用”**：这不是失败。V1 只在引用语境出现明确措辞时标记继承、改进等关系；证据不足时保守回退为 `cites`，避免把普通引用伪造成方法关系。

旧入口 `启动论文研究.cmd` 和旧控制台端口 8766 暂时保留用于兼容。新功能只继续在科研工作台中扩展。
