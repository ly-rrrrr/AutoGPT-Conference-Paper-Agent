# 科研工作台 V1 设计规格

## 1. 目标

把现有论文采集和分析能力发展成独立的本机科研工作台。V1 聚焦真实数据的浏览、查询、任务控制和可解释个性化，不建设三维科研空间、自动方法迁移或完整知识图谱。

成功标准：用户通过一个入口启动系统，在统一网页中看到现有 ECCV/CVPR 资产，检索和查看论文，理解映射与分析状态，并启动、停止或续跑现有流程。

## 2. 技术路线

- 前端：Vue 3、TypeScript、Vite、Vue Router；
- 后端：FastAPI、Pydantic、SQLAlchemy/Alembic；
- 数据库：PostgreSQL；后续语义检索优先评估 pgvector；
- 运行环境：PostgreSQL 使用 Docker，本机启动器管理工作台和既有 AutoGPT 服务；
- 工作流：继续复用 AutoGPT，不把分析逻辑复制进工作台；
- 原始资产：现有 JSONL、HTML 快照、Markdown 和未来 PDF 保持原位并可审计。

V1 不要求把 FastAPI 本身容器化。保持后端运行在本机，可安全复用现有本机 Docker 控制能力；后续接口稳定后再决定整体容器化方式，避免挂载 Docker socket。

## 3. 产品信息架构

### 工作台

- 总览：论文、映射、分析、Likes、任务和异常摘要；
- 最近运行：最近执行状态、开始/结束时间和新增结果；
- 数据资产：各会议、年份和数据层的数量与更新时间。

### 论文资产

- 全部论文：搜索、筛选、排序和分页；
- 顶会论文：按会议、年份和 Topic 浏览；
- 收藏与标签：保存用户判断；
- 论文详情：事实元数据、arXiv 映射、分析问答、证据、Likes、来源和文件状态。

### 采集与分析

- arXiv 映射：状态漏斗、候选证据、查询尝试和错误；
- 论文分析：成功、失败、延期和错误分类；
- 任务队列：当前任务、运行参数和停止操作；
- 运行历史：历史执行、结果增量和失败原因。

### 知识库

- V1 只展示 PDF 是否存在、是否解析、解析器和版本、资产路径及错误；
- 通过适配器接口预留第三方知识库和 PDF 解析器；
- 不在 V1 内实现跨论文 RAG 和知识图谱。

### 个性化

- 关注领域和方法关键词；
- 用户近期工作条目；
- 收藏、排除和标签；
- 可配置的相关度、影响力和新鲜度权重；
- 每个推荐结果展示评分组成，不提供黑盒总分。

## 4. 系统组件

### Vue 前端

负责层级导航、列表、详情、表单和状态展示。前端只通过 FastAPI 获取数据和提交操作，不读取文件、不连接 PostgreSQL、不执行本机命令。

### FastAPI 服务

按领域拆分为：

- `catalog`：会议与论文资产；
- `imports`：JSONL/manifest 导入和同步；
- `pipelines`：映射、分析和 AutoGPT 执行适配；
- `runs`：运行状态、事件和错误；
- `personalization`：关注项、标签、收藏和解释性评分；
- `knowledge`：文档资产及知识库适配器接口。

### PostgreSQL

V1 核心实体：

- `conferences`、`conference_editions`；
- `papers`、`paper_authors`；
- `paper_mappings`、`mapping_candidates`、`mapping_attempts`；
- `paper_analyses`、`paper_answers`；
- `impact_signals`；
- `pipeline_runs`、`pipeline_events`；
- `document_assets`；
- `user_interests`、`recent_works`、`tags`、`paper_tags`、`favorites`；
- `import_batches`。

V1 是单用户本机产品，但用户产生的数据仍使用清晰的数据边界，避免未来升级时无法区分系统数据与用户数据。

### 导入器

导入器扫描明确配置的数据目录，识别映射、分析、Likes 和 manifest 文件。每次导入建立 `import_batch`，记录来源路径、文件哈希、导入时间、解析器版本和计数。采用 upsert，重复执行不得制造重复记录，也不修改原始文件。

### AutoGPT 适配器

V1 复用现有控制台已经验证的本机任务控制逻辑，但将它封装到 FastAPI 的服务层，禁止页面直接调用 Docker。适配器负责服务准备、提交、停止、状态查询和错误归一化。模型调用必须由用户按钮明确触发。

## 5. 关键数据流

### 启动

启动器检查 Docker，启动 PostgreSQL 与需要的 AutoGPT 服务，执行安全的数据库迁移，启动 FastAPI，提供前端静态资源并打开浏览器。已有服务正常时直接复用，避免重复启动和迁移等待。

### 数据同步

用户点击同步或启动时执行轻量变更检测。导入器按文件哈希跳过未变化资产，对变化文件进行幂等 upsert，记录导入批次并刷新页面统计。

### 任务执行

用户在页面确认参数并启动任务。FastAPI 创建本地运行记录，通过 AutoGPT 适配器提交执行，轮询或接收状态，持续更新运行事件。分析结果仍由现有 checkpoint 逐篇落盘；导入器增量同步到 PostgreSQL。

### 论文详情

后端聚合论文事实、映射证据、分析答案、Likes、文件状态和用户内容。所有派生内容携带来源与版本，前端明确区分事实、机器分析和用户判断。

## 6. API 边界

V1 至少提供：

- `GET /api/dashboard`；
- `GET /api/papers`；
- `GET /api/papers/{paper_id}`；
- `GET /api/mappings`；
- `GET /api/runs`、`GET /api/runs/{run_id}`；
- `POST /api/imports/sync`；
- `POST /api/pipelines/mapping/start|stop`；
- `POST /api/pipelines/analysis/start|stop`；
- `GET/PUT /api/preferences`；
- 收藏和标签的增删接口。

写操作仅允许来自本机工作台，并采用 CSRF/Origin 防护。凭证由 AutoGPT 管理，工作台 API 不返回凭证内容。

## 7. 错误与可观测性

统一错误类别：输入错误、服务未就绪、凭证错误、外部限流、外部数据错误、任务冲突和内部错误。页面显示用户可采取的动作，不直接泄露堆栈或敏感内容。

总览至少显示：当前任务、历史累计与本轮增量、最近成功时间、最近失败原因和数据更新时间。运行历史保留关键事件，不把完整 Docker 日志写入产品数据库。

## 8. 验证策略

按项目宪法执行风险分级验证：

- 数据模型和导入：迁移测试、幂等导入测试、业务键与来源测试；
- API：核心列表、详情、同步、启动和停止的针对性测试；
- 前端：总览、列表、详情和任务控制的组件/集成测试；
- 端到端：只保留“启动 → 同步已有数据 → 浏览论文 → 查看任务状态”这一条无付费关键路径；
- 模型调用、arXiv 大批量请求和付费分析使用 fixture/mock，不作为日常验证动作；
- 不运行与工作台改动无关的 AutoGPT 全量测试。

## 9. 交付阶段

1. 项目骨架、PostgreSQL、启动入口和健康检查；
2. 数据模型、迁移与现有资产导入；
3. 层级导航、总览、论文列表和论文详情；
4. 映射、分析、任务状态和运行历史；
5. 收藏、标签、关注项、近期工作和解释性排序；
6. PDF 资产状态与知识库适配器边界。

每个阶段在真实数据上形成可见增量，但不以付费模型调用作为验收条件。

## 10. 非目标

V1 不承诺：三维科研空间、自动方法迁移、跨论文智能综述、完整 RAG、多人协作、云部署、移动端、图数据库、大规模分布式任务和复杂权限系统。这些能力只能在论文资产、证据、任务和个性化基础稳定后重新设计。
